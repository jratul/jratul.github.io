# 유니티 개발 개요와 최근 트렌드, 언리얼과 비교

게임 엔진을 고를 때 가장 먼저 부딪히는 질문은 "유니티냐 언리얼이냐"입니다. 이 글은 유니티의 기본 구조와 최근 흐름을 먼저 정리하고, 언리얼 엔진과 실무 기준으로 비교합니다.

---

## 유니티 개발 개요

### 컴포넌트 기반 아키텍처

유니티는 상속이 아니라 **조합**(Composition) 중심으로 게임 오브젝트를 구성합니다. 모든 것은 `GameObject`이고, 실제 동작은 그 위에 붙는 `Component`들이 담당합니다.

```csharp
using UnityEngine;

public class PlayerMovement : MonoBehaviour
{
    public float speed = 5f;

    void Update()
    {
        float h = Input.GetAxis("Horizontal");
        float v = Input.GetAxis("Vertical");
        transform.Translate(new Vector3(h, 0, v) * speed * Time.deltaTime);
    }
}
```

플레이어 캐릭터 하나에 `PlayerMovement`, `Rigidbody`(물리), `Animator`(애니메이션), `AudioSource`(효과음) 컴포넌트를 각각 붙이는 식으로 기능을 조립합니다. 상속 계층을 깊게 설계할 필요 없이 필요한 컴포넌트만 갈아 끼우면 되므로, 팀원마다 다른 기능을 독립적으로 개발하기 쉽습니다.

### 개발 언어와 에디터

C#을 스크립팅 언어로 쓰고, 에디터에서 씬을 시각적으로 배치하며 컴포넌트 값을 인스펙터 창에서 바로 조정합니다. 코드를 몰라도 디자이너가 수치를 튜닝할 수 있다는 점이 유니티 워크플로우의 핵심입니다.

| 특징 | 내용 |
|------|------|
| 언어 | C# (예전에는 UnityScript/Boo도 지원했으나 현재는 C#만) |
| 렌더 파이프라인 | Built-in, URP(Universal Render Pipeline), HDRP(High Definition RP) 중 선택 |
| 배포 플랫폼 | PC, 콘솔, 모바일(iOS/Android), WebGL, VR/AR 등 폭넓은 크로스 플랫폼 |
| 생태계 | Asset Store — 리소스/플러그인을 사고파는 대규모 마켓플레이스 |
| 강점 분야 | 모바일 게임, 인디 게임, 2D, AR/VR, 하이퍼캐주얼 |

## 유니티 최근 트렌드

### DOTS — 성능을 위한 데이터 지향 설계

기존 컴포넌트 기반 방식(`MonoBehaviour`)은 개발이 편한 대신, 오브젝트 수가 아주 많아지면(예: 수천 개의 유닛이 동시에 움직이는 전략 게임) 성능 한계에 부딪힙니다. **DOTS**(Data-Oriented Technology Stack)는 이 문제를 데이터 지향 설계로 풀기 위한 기술 묶음입니다.

- **ECS**(Entity Component System): 객체지향 대신 데이터를 배열처럼 촘촘하게 배치해 캐시 효율을 높이는 설계
- **Job System**: 멀티스레드로 작업을 안전하게 병렬 분산
- **Burst Compiler**: C# 코드를 고도로 최적화된 네이티브 코드로 컴파일

일반적인 소규모 게임에는 굳이 필요 없지만, 대규모 시뮬레이션이나 수많은 개체를 다뤄야 하는 프로젝트에서는 채택이 늘고 있습니다.

### 요금제 논란과 그 이후

2023년 유니티가 설치 건수 기준으로 과금하는 Runtime Fee 정책을 발표했다가 개발자 커뮤니티의 강한 반발에 부딪혀 철회한 사건이 있었습니다. 이 사건은 유니티에 대한 신뢰에 타격을 줬고, 이후 일부 개발자들이 대안 엔진(Godot 등)으로 이동하는 계기가 되기도 했습니다. 유니티는 이후 요금 정책을 다시 구독 기반 모델 중심으로 정리했습니다. 엔진을 장기간 채택할 때는 라이선스/과금 정책 변경 리스크도 함께 고려해야 한다는 교훈을 남긴 사례입니다.

### AI 도구 통합

Unity Muse(텍스트로 애니메이션·텍스처 등 에셋을 생성), Unity Sentis(온디바이스 AI 추론을 게임에 내장) 같은 AI 기반 도구를 엔진에 통합하는 흐름이 이어지고 있습니다. 콘텐츠 제작 속도를 높이거나, 게임 안에 AI 추론(예: NPC 행동, 이미지 인식)을 직접 넣는 방향입니다.

### 여전히 강한 모바일/인디 지배력

가볍고 빌드 크기가 작아 모바일 게임, 특히 하이퍼캐주얼/캐주얼 장르에서는 여전히 압도적으로 많이 쓰입니다. 인디 개발자와 소규모 팀의 진입 장벽이 낮다는 점도 이 지위를 유지하는 이유입니다.

## 언리얼 엔진 개요

### C++ + 블루프린트

언리얼은 C++이 기본이지만, **블루프린트**(Blueprint)라는 노드 기반 비주얼 스크립팅으로 코드를 거의 몰라도 게임 로직을 짤 수 있습니다. 성능이 중요한 부분은 C++로, 나머지 로직은 블루프린트로 짜는 조합이 흔합니다.

```
[Event BeginPlay] → [Print String "Hello"] → [Delay 1.0] → [Destroy Actor]
```

블루프린트는 위와 같은 노드를 선으로 연결하는 방식이라, 프로그래머가 아닌 기획자/디자이너도 프로토타입 로직을 직접 만들 수 있습니다.

### 압도적인 그래픽 퀄리티

언리얼 엔진 5부터는 그래픽 품질을 끌어올리는 두 핵심 기술이 기본 탑재됐습니다.

| 기술 | 역할 |
|------|------|
| Nanite | 수억 폴리곤급 초고밀도 지오메트리를 실시간으로 처리하는 가상화 지오메트리 시스템 — 아티스트가 폴리곤 수를 신경 쓰지 않고 영화급 3D 모델을 그대로 가져다 쓸 수 있게 함 |
| Lumen | 실시간 전역 조명(Global Illumination) — 조명을 미리 구워두지(bake) 않아도 동적으로 사실적인 빛 반사를 계산 |

이 덕분에 AAA급 콘솔/PC 게임, 그리고 영화·건축 시각화처럼 사실적인 렌더링이 핵심인 분야에서 압도적으로 선호됩니다.

## 언리얼 최근 트렌드

### 버추얼 프로덕션의 확산

LED 월(대형 LED 스크린)에 언리얼로 실시간 렌더링한 배경을 띄워놓고 그 앞에서 실사 촬영을 하는 **버추얼 프로덕션**(Virtual Production) 방식이 영화·드라마 제작 현장에 확산되고 있습니다(디즈니 '만달로리안' 제작 방식으로 널리 알려짐). 그린스크린 합성보다 배우의 몰입감과 실시간 라이팅 일치도가 높다는 장점이 있습니다.

### MetaHuman — 디지털 휴먼 제작

사실적인 디지털 인간 캐릭터를 빠르게 만들 수 있는 MetaHuman 도구가 게임뿐 아니라 영상 제작, 가상 인플루언서 제작에도 쓰이며 활용 범위를 넓히고 있습니다.

### UEFN — 포트나이트 생태계

Unreal Editor for Fortnite(UEFN)는 포트나이트 안에서 언리얼 엔진 수준의 도구로 자체 게임 모드/맵을 만들어 배포할 수 있게 하는 플랫폼입니다. 언리얼의 기술력을 포트나이트라는 거대한 이용자 기반과 결합해 크리에이터 생태계를 넓히는 흐름을 보여줍니다.

## 유니티 vs 언리얼 비교

| | 유니티 | 언리얼 엔진 |
|---|---|---|
| 주 언어 | C# | C++ (+ 블루프린트) |
| 러닝 커브 | 상대적으로 완만 | C++ 비중이 크면 가파름, 블루프린트만 쓰면 완만 |
| 그래픽 퀄리티(기본값) | 준수하지만 별도 튜닝 필요 | Nanite/Lumen으로 기본값부터 사실적 |
| 빌드 크기/경량성 | 가볍고 모바일에 유리 | 상대적으로 무거움 |
| 강점 플랫폼 | 모바일, 인디, 2D, AR/VR | 콘솔/PC AAA, 영화/버추얼 프로덕션 |
| 에셋 생태계 | Asset Store | Fab(구 Marketplace) |
| 라이선스 | 구독 기반(매출 구간별 요금제) | 매출 임계값 이하 무료, 이후 로열티 |
| 대표 사례 | 모바일 캐주얼 게임, 인디 게임 다수 | AAA 콘솔 게임, 영화 VFX/버추얼 프로덕션 |

## 정리 — 언제 무엇을 고를까

| 상황 | 추천 |
|---|---|
| 모바일/캐주얼 게임을 빠르게 출시 | 유니티 |
| 소규모 팀, C# 친화적 개발자 구성 | 유니티 |
| AAA급 콘솔/PC 게임, 사실적인 그래픽이 핵심 | 언리얼 엔진 |
| 영상/영화 VFX, 버추얼 프로덕션 | 언리얼 엔진 |
| 대규모 시뮬레이션(수천 개체 이상) | 유니티(DOTS) 또는 언리얼 둘 다 검토 가치 있음 |
| 비개발자도 로직을 직접 짜야 함 | 언리얼(블루프린트)이 진입장벽이 더 낮은 편 |

두 엔진 모두 최근에는 AI 기반 콘텐츠 생성 도구를 적극적으로 통합하고, 비개발자도 다룰 수 있는 비주얼 스크립팅을 강화하는 방향으로 함께 움직이고 있습니다. "그래픽 퀄리티가 최우선이면 언리얼, 가볍고 빠른 크로스 플랫폼 배포가 우선이면 유니티"라는 큰 축은 여전히 유효하지만, 두 엔진의 격차는 점점 좁혀지는 추세입니다.
