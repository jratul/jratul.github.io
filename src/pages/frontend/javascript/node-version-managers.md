# nvm vs n vs Volta: Node 버전 관리 도구 비교

프로젝트마다 요구하는 Node 버전이 다르면, 시스템에 Node를 하나만 설치해서는 감당이
안 됩니다. 여러 버전을 설치해두고 프로젝트별로 전환해주는 도구가 필요한데, 대표적으로
nvm, n, Volta 세 가지가 있습니다. 셋 다 "여러 Node 버전을 관리한다"는 목표는 같지만
동작 방식이 꽤 다릅니다.

---

## 공통 문제: 왜 버전 관리 도구가 필요한가

```
프로젝트 A → Node 18 필요 (레거시, engines 필드에 명시)
프로젝트 B → Node 22 필요 (최신 기능 사용)
프로젝트 C → Node 20 필요 (LTS 고정)
```

시스템에 Node를 하나만 깔아두면 프로젝트를 오갈 때마다 재설치해야 합니다. 버전 관리
도구는 여러 버전을 나란히 설치해두고, 지금 터미널/프로젝트에서 어떤 버전을 쓸지
빠르게 전환해줍니다.

---

## nvm (Node Version Manager)

가장 오래되고 널리 쓰이는 도구입니다. 셸 스크립트로 구현되어 있고, `nvm` 명령 자체가
셸 함수로 등록되어 `PATH`를 조작하는 방식으로 동작합니다.

```bash
# 설치
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.0/install.sh | bash

# 버전 설치 및 전환
nvm install 20
nvm use 20
nvm install --lts
```

**프로젝트별 버전 고정**: `.nvmrc` 파일에 버전을 적어두고 `nvm use`만 실행하면 그
버전으로 전환됩니다.

```
// .nvmrc
20.11.0
```

```bash
nvm use   # .nvmrc 읽어서 자동으로 해당 버전으로 전환
```

**한계**:
- `cd`로 프로젝트 디렉토리를 옮겨도 자동으로 전환되지 않습니다 — 매번 `nvm use`를
  직접 실행해야 하고, 자동화하려면 셸 설정(`.zshrc`/`.bashrc`)에 별도 훅을 추가해야
  합니다.
- 셸 함수 기반이라 새 터미널을 열 때마다 초기화 스크립트를 로드하는 비용이 있어
  다른 도구보다 셸 시작이 느린 편입니다.
- 공식 지원은 Unix 계열(macOS/Linux) 중심이고, Windows는 `nvm-windows`라는
  별도의(호환은 되지만 다른 코드베이스인) 프로젝트를 써야 합니다.

---

## n

TJ Holowaychuk이 만든, nvm보다 훨씬 단순한 도구입니다. 셸 함수 대신 실제로 시스템의
Node 바이너리를 설치된 버전으로 **교체**하는 방식으로 동작합니다.

```bash
# 설치 (npm으로 설치)
npm install -g n

# 버전 설치 및 즉시 전환
n 20.11.0
n lts     # 최신 LTS로 전환
n latest  # 최신 버전으로 전환
```

**동작 방식 차이**: nvm은 셸 세션마다 `PATH`에서 어떤 버전을 가리킬지 함수로 계산하지만,
n은 `/usr/local/bin/node`처럼 고정된 경로의 실행 파일 자체를 바꿔치기합니다. 그래서
셸 함수 오버헤드가 없고 더 빠르지만, 그만큼 "이 프로젝트에서만 이 버전" 같은 프로젝트
단위 자동 전환은 nvm보다도 더 지원이 약합니다.

**한계**:
- `.nvmrc` 같은 프로젝트별 설정 파일 컨벤션이 없습니다(버전은 항상 전역으로
  바뀝니다).
- Windows는 지원하지 않습니다 — 유닉스 계열 파일 시스템 권한 모델에 의존하기
  때문입니다.

---

## Volta

가장 최근에 나온 도구로, Rust로 작성된 바이너리입니다. nvm/n과 가장 큰 차이는
**프로젝트 디렉토리에 들어가기만 하면 자동으로 올바른 버전이 활성화**된다는 점입니다
— 별도로 `use` 명령을 실행할 필요가 없습니다.

```bash
# 설치
curl https://get.volta.sh | bash

# 버전 설치
volta install node@20

# 프로젝트에 버전 고정 (package.json에 기록됨)
volta pin node@20.11.0
volta pin npm@10.2.4
```

`volta pin`을 실행하면 `package.json`에 버전이 직접 기록됩니다.

```json
{
  "volta": {
    "node": "20.11.0",
    "npm": "10.2.4"
  }
}
```

이 프로젝트 디렉토리에서 `node -v`를 실행하면, Volta가 설치한 **shim**(실제 실행
파일을 가로채는 얇은 바이너리)이 현재 디렉토리를 탐색해 `package.json`의 `volta`
필드를 찾고, 자동으로 올바른 버전을 실행합니다. `cd`만 하면 되고, 셸 설정에 훅을
추가할 필요도 없습니다.

**Node 외에 패키지 매니저까지 관리**: nvm/n은 Node 버전만 다루지만, Volta는 npm,
yarn, pnpm 버전까지 같은 방식으로 프로젝트에 고정할 수 있습니다. 팀원 전체가 정확히
같은 Node + 패키지 매니저 조합을 쓰게 강제하기 좋습니다.

**한계**:
- shim 기반이라 최초 실행 시 아주 약간의 오버헤드가 있습니다(사실상 체감하기 어려운
  수준).
- 생태계가 nvm보다 작아서, nvm 전용으로 작성된 CI 스크립트나 문서를 그대로 옮기려면
  약간의 수정이 필요할 수 있습니다.

## 비교 정리

| | nvm | n | Volta |
|---|---|---|---|
| 구현 방식 | 셸 함수 + PATH 조작 | 바이너리 직접 교체 | Rust shim |
| 프로젝트 자동 전환 | ❌ (`.nvmrc` + `nvm use` 수동) | ❌ | ✅ (`cd`만 하면 자동) |
| 설정 파일 | `.nvmrc` | 없음(전역 전환) | `package.json`의 `volta` 필드 |
| 관리 대상 | Node만 | Node만 | Node + npm/yarn/pnpm |
| Windows 지원 | ❌ (별도 `nvm-windows` 필요) | ❌ | ✅ 공식 지원 |
| 속도 | 셸 시작 시 오버헤드 있음 | 빠름 | 빠름 |

---

## 언제 뭘 쓰면 좋은가

- **nvm**: 가장 널리 쓰이고 정보/커뮤니티가 많아서, 익숙하고 자동 전환이 크게
  아쉽지 않다면 무난한 기본 선택.
- **n**: 프로젝트마다 버전을 자주 바꿀 일이 없고, 전역 Node 버전을 빠르고 간단하게만
  관리하고 싶을 때.
- **Volta**: 여러 프로젝트를 오가며 Node/패키지 매니저 버전이 자주 다르고, 특히
  **팀 전체가 같은 버전을 쓰도록 강제**하고 싶거나 Windows 환경이 섞여 있을 때 가장
  유리합니다.

세 도구 모두 같은 머신에 동시에 설치할 수는 있지만, 서로의 shim/PATH 조작 방식이
충돌할 수 있어 실제로는 하나만 골라 쓰는 걸 권장합니다.
