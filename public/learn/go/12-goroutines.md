Go의 동시성 모델은 **고루틴**(goroutine)이라는 경량 실행 단위를 중심으로 돌아갑니다. OS
스레드를 직접 다루는 언어와 달리, Go는 런타임이 자체적으로 스케줄링하는 훨씬 가벼운
단위를 제공해서 수천, 수만 개를 동시에 띄워도 부담이 크지 않습니다.

---

## 고루틴이란

고루틴은 Go 런타임이 관리하는 경량 스레드입니다. OS 스레드를 만들 때는 보통 수 MB의
스택을 미리 할당하지만, 고루틴은 2KB 수준의 아주 작은 스택으로 시작해서 필요할 때
동적으로 늘어납니다. 그래서 수만 개의 고루틴을 동시에 띄우는 것도 흔한 일입니다.

함수 호출 앞에 `go` 키워드만 붙이면 새 고루틴에서 그 함수가 실행됩니다.

```go
package main

import (
	"fmt"
	"time"
)

func sayHello() {
	fmt.Println("Hello from goroutine")
}

func main() {
	go sayHello() // 새 고루틴에서 실행

	time.Sleep(100 * time.Millisecond) // 임시방편: 고루틴이 끝날 시간을 벌어줌
	fmt.Println("main 종료")
}
```

`go 함수호출()` 형태로 호출하면, 그 함수 실행은 별도의 고루틴에 맡겨지고 `main`은 곧바로
다음 줄로 넘어갑니다. 함수의 반환값을 직접 받을 수는 없고(대신 채널을 씁니다, 다음 강
참고), 실행 결과를 기다리지도 않습니다.

익명 함수(클로저)도 그대로 고루틴으로 띄울 수 있습니다.

```go
func main() {
	go func() {
		fmt.Println("익명 함수도 고루틴으로")
	}()

	time.Sleep(100 * time.Millisecond)
}
```

## M:N 스케줄링과 GOMAXPROCS

OS 스레드 하나에 고루틴 하나를 대응시키면 수만 개의 고루틴이 수만 개의 OS 스레드를
만들어버려 컨텍스트 스위칭 비용이 감당이 안 됩니다. Go 런타임은 이 문제를 **M:N
스케줄링**으로 해결합니다.

| 구성요소 | 의미 |
| --- | --- |
| G (Goroutine) | 실행할 작업 단위 |
| M (Machine) | 실제 OS 스레드 |
| P (Processor) | 고루틴을 스레드에 배분하는 스케줄링 컨텍스트 |

수만 개의 고루틴(G)이 소수의 OS 스레드(M) 위에서 P를 매개로 번갈아 실행됩니다. 즉
"M개의 OS 스레드 위에 N개의 고루틴을 얹는다"는 뜻에서 M:N 스케줄링이라고 부릅니다.
개발자는 이 스케줄링을 신경 쓸 필요 없이 그냥 `go` 키워드만 붙이면 됩니다.

동시에 실행에 사용할 최대 OS 스레드(P) 개수는 `GOMAXPROCS`로 조절합니다. 기본값은
머신의 논리 CPU 코어 수입니다.

```go
package main

import (
	"fmt"
	"runtime"
)

func main() {
	fmt.Println("CPU 코어 수:", runtime.NumCPU())
	fmt.Println("GOMAXPROCS:", runtime.GOMAXPROCS(0)) // 0을 넘기면 현재 값 조회만

	runtime.GOMAXPROCS(2) // 최대 2개의 OS 스레드만 사용하도록 제한
}
```

대부분의 경우 기본값을 그대로 두는 게 좋습니다. I/O 대기가 많은 프로그램이라면 코어
수보다 많은 고루틴을 띄워도 스케줄러가 알아서 대기 중인 고루틴을 빼고 다른 고루틴을
그 자리에 밀어 넣어 처리량을 끌어올립니다.

## 흔한 실수 — main이 먼저 끝나버린다

가장 많이 겪는 실수는 `main` 함수가 고루틴이 실행을 마치기도 전에 먼저 종료돼버리는
경우입니다. Go 프로그램은 `main` 함수가 반환되는 순간 그 안에서 아직 끝나지 않은
고루틴이 있어도 신경 쓰지 않고 프로세스를 즉시 종료합니다.

```go
package main

import "fmt"

func main() {
	go fmt.Println("나는 출력될 수도, 안 될 수도 있다")
	// main이 곧바로 끝나버려서 위 고루틴은 실행될 기회를 못 얻을 가능성이 높다
}
```

이 코드는 실행할 때마다 결과가 다를 수 있습니다. `go` 문이 새 고루틴을 예약하는 순간
`main`도 다음 줄로 진행하는데, 마침 다음 줄이 함수의 끝이라 프로그램 자체가 종료돼버리기
때문입니다. 위 예제처럼 `time.Sleep`으로 시간을 버는 것은 **디버깅 임시방편일 뿐** 실제
코드에 쓰면 안 되는 방법입니다. 고루틴이 얼마나 걸릴지 예측할 수 없고, 필요 이상으로
오래 기다리게 될 수도 있기 때문입니다.

올바른 해결책은 "고루틴이 끝날 때까지 기다리는" 동기화 도구를 쓰는 것입니다. Go는 이를
위해 채널(channel)과 `sync.WaitGroup`을 제공하는데, 채널은 다음 강, `sync.WaitGroup`은
그다음 강에서 다룹니다. 지금은 "고루틴을 띄우고 나면 반드시 명시적으로 완료를 기다려야
한다"는 원칙만 기억해두면 됩니다.

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var wg sync.WaitGroup

	wg.Add(1) // 기다릴 고루틴 개수를 미리 등록
	go func() {
		defer wg.Done() // 종료 시점에 카운트 감소
		fmt.Println("이제는 확실히 출력된다")
	}()

	wg.Wait() // 등록된 고루틴이 모두 Done을 호출할 때까지 대기
}
```

`sync.WaitGroup`의 자세한 사용법은 14강("동시성 패턴")에서 다룹니다.

## 반복문과 클로저 — 루프 변수 캡처 문제

반복문 안에서 고루틴을 여러 개 띄울 때 클로저가 반복문 변수를 어떻게 캡처하는지가
Go 버전에 따라 다르게 동작해서 자주 헷갈리는 포인트입니다.

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var wg sync.WaitGroup

	for i := 0; i < 3; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			fmt.Println(i) // Go 1.22 이전: 예상과 다르게 동작할 수 있음
		}()
	}

	wg.Wait()
}
```

| Go 버전 | `for i := 0; ...` 루프 변수 `i` | 위 예제 출력 |
| --- | --- | --- |
| 1.21 이하 | 루프 전체에서 **변수 하나를 공유** | `2, 2, 2` (순서/값 불확실, 대부분 동일 값 반복) |
| 1.22 이상 | 매 반복마다 **새 변수를 생성** | `0, 1, 2` (순서는 고루틴 스케줄링에 따라 달라질 수 있지만 값 자체는 매번 다름) |

Go 1.21 이하에서는 `for` 루프의 `i`가 반복 전체에서 재사용되는 하나의 변수였기 때문에,
고루틴이 실제로 실행되는 시점에는 이미 루프가 다 돌아 `i`가 마지막 값(3, 조건에 안 맞아
루프가 끝난 상태라면 그 직전 값인 2)이 되어 있는 경우가 흔했습니다. 그래서 이 시절 코드는
클로저 안으로 값을 명시적으로 넘기는 방식이 표준 관용구였습니다.

```go
for i := 0; i < 3; i++ {
	wg.Add(1)
	go func(n int) { // 매개변수로 받아서 그 시점 값을 값 복사로 고정
		defer wg.Done()
		fmt.Println(n)
	}(i) // 호출 시점의 i 값을 그대로 넘김
}
```

또는 루프 안에서 새 지역 변수를 만들어 캡처시키는 방식도 자주 쓰였습니다.

```go
for i := 0; i < 3; i++ {
	i := i // 반복마다 새 지역 변수 생성, 오른쪽 i는 바깥(루프) 변수
	wg.Add(1)
	go func() {
		defer wg.Done()
		fmt.Println(i)
	}()
}
```

Go 1.22부터는 언어 스펙 자체가 바뀌어서 `for` 루프의 반복 변수가 매 반복마다 새로
생성됩니다. 그래서 위와 같은 우회 없이 클로저 안에서 바로 `i`를 참조해도 각 반복 시점의
값이 그대로 캡처됩니다. 다만 여전히 매개변수로 넘기는 방식이 "이 값은 이 시점에 고정된다"는
의도를 코드로 명확히 드러내므로, 오래된 코드베이스나 여러 버전을 넘나드는 프로젝트에서는
습관적으로 유지하는 경우도 많습니다.

## 정리

| 개념 | 설명 |
| --- | --- |
| `go 함수()` | 새 고루틴에서 함수 실행, 반환값을 직접 받을 수 없음 |
| 경량성 | 초기 스택 2KB 수준, 수만 개 동시 실행 가능 |
| M:N 스케줄링 | 다수의 고루틴(G)을 소수의 OS 스레드(M) 위에 P를 매개로 배분 |
| `GOMAXPROCS` | 동시에 사용할 최대 OS 스레드 수, 기본값은 논리 코어 수 |
| main 조기 종료 | `main`이 끝나면 미완료 고루틴이 있어도 프로세스가 즉시 종료됨 |
| 루프 변수 캡처 | Go 1.22 미만은 매개변수로 값을 넘기거나 `i := i`로 새 변수를 만들어야 안전 |

다음 강에서는 고루틴 간에 값을 안전하게 주고받고 동기화하는 핵심 도구인 채널(channel)을
다룹니다.
