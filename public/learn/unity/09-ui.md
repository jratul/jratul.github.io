## Unity의 UI 시스템

| | uGUI (Unity UI) | UI Toolkit |
|--|-----------------|------------|
| 방식 | GameObject + 컴포넌트 | UXML(마크업) + USS(스타일) — 웹과 비슷 |
| 레이아웃 | RectTransform, 앵커 | Flexbox (Yoga 엔진) |
| 월드 공간 UI | 지원 (머리 위 HP바 등) | Unity 6.2부터 지원 |
| 에디터 확장 | X | O (에디터 UI의 표준) |
| 현재 위치 | 게임 런타임 UI의 오랜 표준, 자료가 가장 많음 | Unity가 장기적으로 밀고 있는 방향 |

두 시스템은 한 프로젝트에서 함께 쓸 수 있습니다. 이 레슨은 가장 많이 쓰이는 uGUI를 중심으로 하고 UI Toolkit을 간단히 다룹니다.

## uGUI 기본 구조

```
Canvas                ← 모든 UI의 루트 (Canvas, CanvasScaler, GraphicRaycaster)
├── Panel (Image)
│   ├── Title (TextMeshPro - Text)
│   ├── StartButton (Button)
│   │   └── Text (TMP)
│   └── VolumeSlider (Slider)
EventSystem           ← 입력을 UI로 전달 (씬에 하나 필요)
```

> 텍스트는 구형 `Text` 대신 **TextMeshPro(TMP)**를 씁니다. 해상도와 무관하게 선명하고(SDF 렌더링), 리치 텍스트 기능이 풍부합니다. 한글을 쓰려면 한글 글리프를 포함한 **TMP Font Asset**을 따로 만들어야 합니다(Window → TextMeshPro → Font Asset Creator).

### Canvas Render Mode

| 모드 | 설명 | 용도 |
|------|------|------|
| **Screen Space - Overlay** | 화면 맨 위에 그림, 카메라 무관 | 일반적인 HUD, 메뉴 |
| **Screen Space - Camera** | 지정한 카메라 앞 일정 거리에 그림 | UI에 파티클/3D 효과를 섞을 때 |
| **World Space** | 3D 공간의 오브젝트처럼 존재 | 캐릭터 머리 위 HP바, 게임 내 모니터 |

## RectTransform과 앵커

UI 요소는 `Transform` 대신 `RectTransform`을 씁니다. 핵심은 **앵커(Anchor)** — 부모 영역의 어느 지점을 기준으로 배치할지 정합니다.

```
앵커가 한 점일 때 (min == max)
  → 부모 크기가 변해도 크기 유지, 기준점과의 거리 유지
  예: 우측 상단 고정 설정 버튼

앵커가 벌어져 있을 때 (min != max)
  → 부모 크기에 비례해서 늘어남
  예: 화면 하단 전체를 채우는 바 (anchorMin (0,0), anchorMax (1,0))
```

Inspector의 앵커 프리셋에서 `Alt`를 누르고 클릭하면 위치까지 함께 맞춰집니다.

### Canvas Scaler — 해상도 대응

**UI Scale Mode = Scale With Screen Size**로 두고 기준 해상도(예: 1920×1080)를 지정합니다.

- **Match Width Or Height**: 0이면 가로 기준, 1이면 세로 기준으로 스케일. 세로 모드 모바일 게임은 보통 가로 기준(0)에 가깝게, 가로 모드는 0.5 근처로 맞춥니다.
- 노치/펀치홀 대응은 `Screen.safeArea`로 안전 영역 패널의 앵커를 조정합니다.

```csharp
public class SafeArea : MonoBehaviour
{
    void Awake()
    {
        var rt = (RectTransform)transform;
        Rect safe = Screen.safeArea;
        Vector2 min = safe.position;
        Vector2 max = safe.position + safe.size;
        min.x /= Screen.width;  min.y /= Screen.height;
        max.x /= Screen.width;  max.y /= Screen.height;
        rt.anchorMin = min;
        rt.anchorMax = max;
    }
}
```

## 버튼과 이벤트

```csharp
using TMPro;
using UnityEngine;
using UnityEngine.UI;

public class MainMenu : MonoBehaviour
{
    [SerializeField] private Button startButton;
    [SerializeField] private Slider volumeSlider;
    [SerializeField] private TMP_Text scoreText;

    void OnEnable()
    {
        startButton.onClick.AddListener(OnStart);
        volumeSlider.onValueChanged.AddListener(OnVolume);
    }

    void OnDisable()
    {
        startButton.onClick.RemoveListener(OnStart);
        volumeSlider.onValueChanged.RemoveListener(OnVolume);
    }

    private void OnStart() => SceneLoader.Load("Stage1");
    private void OnVolume(float v) => AudioListener.volume = v;

    public void SetScore(int score)
    {
        scoreText.SetText("Score: {0}", score);  // 문자열 할당 없이 숫자 포맷
    }
}
```

> `scoreText.text = $"Score: {score}"`는 매번 새 문자열을 할당합니다. 매 프레임 바뀌는 텍스트는 TMP의 `SetText(format, number)`를 쓰면 GC를 줄일 수 있습니다.

## 레이아웃 그룹

| 컴포넌트 | 역할 |
|----------|------|
| `HorizontalLayoutGroup` / `VerticalLayoutGroup` | 자식을 가로/세로로 나열 |
| `GridLayoutGroup` | 격자 배치 (인벤토리 슬롯) |
| `ContentSizeFitter` | 내용에 맞춰 자신의 크기 조절 |
| `LayoutElement` | 자식의 최소/선호 크기 지정 |
| `ScrollRect` | 스크롤 영역 |

> 레이아웃 그룹은 자식이 바뀔 때마다 전체 레이아웃을 다시 계산합니다. 항목이 수백 개인 리스트는 화면에 보이는 셀만 재사용하는 **가상화(Recycling) 스크롤**을 구현하거나 라이브러리를 씁니다.

## uGUI 성능: Canvas 분리

Canvas 안의 요소가 **하나라도 바뀌면 그 Canvas 전체의 메시를 다시 만듭니다(rebuild).** 매 프레임 바뀌는 타이머 텍스트가 정적인 메뉴와 같은 Canvas에 있으면 메뉴 전체가 매 프레임 재빌드됩니다.

```
❌ 하나의 Canvas
   Canvas
   ├── 정적 배경, 프레임, 아이콘 수십 개
   └── 매 프레임 바뀌는 타이머

✅ 자주 바뀌는 것을 하위 Canvas로 분리
   Canvas (Static)
   ├── 정적 배경, 프레임, 아이콘
   └── Canvas (Dynamic)   ← 중첩 Canvas는 독립적으로 재빌드
       └── 타이머
```

그 밖의 팁:
- 클릭할 필요 없는 Image/Text는 **Raycast Target**을 꺼서 입력 검사 비용을 줄입니다.
- UI를 숨길 땐 `SetActive(false)`보다 `CanvasGroup.alpha = 0` + `blocksRaycasts = false` 또는 Canvas 컴포넌트를 끄는 쪽이 재활성화 비용이 적습니다.

## 월드 공간 HP바

```csharp
public class HpBar : MonoBehaviour
{
    [SerializeField] private Image fill;   // Image Type = Filled
    [SerializeField] private Health health;
    private Camera cam;

    void Awake() => cam = Camera.main;

    void OnEnable()  => health.OnHpChanged += Refresh;
    void OnDisable() => health.OnHpChanged -= Refresh;

    void LateUpdate()
    {
        // 항상 카메라를 바라보게 (빌보드)
        transform.forward = cam.transform.forward;
    }

    private void Refresh(int hp, int max) => fill.fillAmount = (float)hp / max;
}
```

## UI Toolkit 맛보기

웹 개발 경험이 있다면 익숙한 구조입니다.

```xml
<!-- MainMenu.uxml -->
<ui:UXML xmlns:ui="UnityEngine.UIElements">
  <ui:VisualElement class="menu">
    <ui:Label text="My Game" class="title" />
    <ui:Button name="start-button" text="시작" class="menu-button" />
    <ui:Button name="quit-button" text="종료" class="menu-button" />
  </ui:VisualElement>
</ui:UXML>
```

```css
/* MainMenu.uss */
.menu {
    flex-grow: 1;
    align-items: center;
    justify-content: center;
}
.title { font-size: 64px; color: white; }
.menu-button { width: 300px; height: 60px; margin: 8px; }
.menu-button:hover { background-color: rgb(80, 80, 200); }
```

```csharp
using UnityEngine;
using UnityEngine.UIElements;

[RequireComponent(typeof(UIDocument))]
public class MainMenuView : MonoBehaviour
{
    void OnEnable()
    {
        var root = GetComponent<UIDocument>().rootVisualElement;
        root.Q<Button>("start-button").clicked += OnStart;
        root.Q<Button>("quit-button").clicked += Application.Quit;
    }

    private void OnStart() { /* ... */ }
}
```

- **UI Builder** 창에서 드래그 앤 드롭으로 UXML을 편집할 수 있습니다.
- 데이터 바인딩(Unity 6의 런타임 바인딩)으로 C# 프로퍼티와 UI를 연결할 수 있습니다.
- 메뉴·인벤토리·설정처럼 화면 공간의 복잡한 UI에 강하고, 에디터 확장 툴은 사실상 UI Toolkit이 표준입니다.

---

## 정리

- uGUI는 Canvas + RectTransform + 앵커 구조이고, 텍스트는 TextMeshPro를 씁니다.
- Canvas Scaler(Scale With Screen Size)와 Safe Area로 해상도·노치에 대응합니다.
- 자주 바뀌는 UI는 하위 Canvas로 분리하고, 불필요한 Raycast Target은 끕니다.
- UI Toolkit은 UXML/USS 기반의 웹 스타일 UI이며 에디터 확장의 표준입니다.
